# C++20 course sources and verification

The course contains 180 original skills in 45 four-step topics across 12 units. Each atom has two short lesson paragraphs, a complete runnable C++20 example, three concept/trace/contract questions, a compiled function exercise, and two mastery-card templates. There are 720 assessments (540 choice and 180 code) and 360 cards. The final atom in each topic is its stable `cpp-<topic>` graph node; stages 2–4 require the preceding atom. Topic roots reference actual language, ownership, container, or synchronization prerequisites. Learning C++ does not require completing the Python course.

## Reference material inspected

Primary language and library contracts were checked against the [C++ working draft](https://eel.is/c++draft/), including [data races](https://eel.is/c++draft/intro.races), [atomic ordering](https://eel.is/c++draft/atomics.order), and [container requirements](https://eel.is/c++draft/container.requirements.general). The working draft evolves beyond C++20; the course uses only C++20-or-earlier facilities. Ownership, lifetime, and interface design were checked against the [C++ Core Guidelines](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines). Compilation-stage descriptions use the [GCC driver documentation](https://gcc.gnu.org/onlinedocs/gcc/Overall-Options.html).

On 2026-10-02 the ordinary public HTML of the [GetCracked homepage](https://getcracked.io/), [question catalog](https://getcracked.io/questions), [problem catalog](https://getcracked.io/problems), [quiz catalog](https://getcracked.io/quizzes), [progress tree](https://getcracked.io/progress-tree), and [blog index](https://getcracked.io/blog) was read successfully (HTTP 200). These pages informed the selection of developer interview topics: C++, concurrency, operating systems, computer architecture, language knowledge, system design, order books, and ring buffers. Public catalog metadata was sufficient; authenticated or paid question bodies were not needed.

The supplied local GetCracked directory was also inspected across all 500 question rows, 200 problem rows, and four quiz records. It is a duplicated and partially malformed topic snapshot: only 20 unique question metadata records and 20 unique problem metadata records appear. Some `language` fields contain difficulty labels, and the scraped `C` label loses `++`. Counts therefore describe records inspected, not a bank of 700 unique imported exercises. Quiz metadata includes concurrency, intern developer, and junior developer C++ coverage. Compensation records and scraper scripts are not used by this curriculum.

All teaching text, examples, questions, solutions, and cards are authored for Lessdumb. No GetCracked proprietary question, paid problem body, or solution is copied into the app. The catalog inspires coverage rather than supplying an imported problem bank.

## Coverage and graph

- Values and control: initialization, integer/floating arithmetic, overflow checks, enums, type deduction, branches, loop bounds, function contracts, overloads, and default arguments.
- Borrowing and ownership: references, nullable pointers, valid array ranges, spans, string views, lifetime, initialization/destruction order, RAII, exception cleanup, exclusive/shared/weak ownership, moves, `noexcept`, independent copies, and the rule of zero.
- Standard library and generic code: strings and integer parsing, vector size/capacity/invalidation, safe erase loops, ordered and hash maps, sets, min/max heaps, deques, queue adapters, sorting, searching, accumulation, erase-remove, lambda capture, function/class templates, forwarding, concepts, `requires`, `if constexpr`, compile-time tables, callable objects, and `std::function`.
- Errors and tooling: optional/variant/visitors, exceptions, checked access, commit-after-validation, virtual interfaces/destructors, slicing, composition, declarations/definitions, namespaces, internal linkage, inline entities, assertions, empty cases, round-trip properties, and numeric tolerance.
- Concurrency: joining threads, copied inputs, independent output partitions, `jthread`, RAII mutex ownership, atomic read-modify-write, coordinated multi-locks, condition-variable predicates/shutdown, atomic compare/exchange, relaxed counters, release/acquire publication, sequential consistency, retry loops, futures/promises, and exception propagation.
- Architecture and performance: explicit page-table models, alignment, persistent/local storage, contiguous and row-major traversal, structure of arrays, false-sharing layout models, elapsed units, medians, nearest-rank percentiles, and operation-count models.
- Applications: aggregate/cancel/select order-book levels, spreads and size imbalance, bounded FIFO rings and a real threaded SPSC publication protocol, big-endian decoding, frame bounds, sequence gaps, run-length encoding, integer notional/position checks, expiry boundaries, backpressure, event identities, ordered replay/snapshots, deterministic tie-breaks, integer ticks, reproducible engines, and a composed risk-event transition.

The graph preserves prerequisite eligibility independently of display filtering. Testing requires sequence algorithms; threads and address models require lambda captures, with vectors included through their ancestors. The reference-return step checks a real alias to caller-owned scalar storage before container borrowing. Every implementation exercise displays its canonical assertions above the editor, including required boundary behavior. A learner cannot unlock a later atom using only reading, hints, or repeated evidence for one question; the common engine requires independent choice and compiled-code evidence. A failed prerequisite blocks its descendants while preserving their saved mastery evidence for later repair.

## Native verification

All 180 trusted solutions passed their independent assertion harnesses and all 180 complete examples executed under Apple clang 21.0.0 with `-std=c++20 -pthread`. Namespace-isolated batches keep compilation efficient while preserving independent function and helper scopes. Actual printed outputs were recorded from execution, including boolean and string output formatting. A further 80,746 independent native property comparisons covered alignment rounding, overflow rejection, row-major bounds, signed minimum magnitude, SPSC wrap/reuse, position limits, and explicit cache-line models. The retained `tests/cpp-curriculum.test.ts` regression performs four native compilation batches directly from the checked-in catalog: trusted reference harnesses, complete examples with exact stdout comparisons, TODO starters, and empty submissions. It selects `CXX` when provided, otherwise discovers clang++ or g++; all generated files are cleaned from an operating-system temporary directory. Unlimited compiler diagnostics with per-skill source locations prove an independent rejection for every one of the 180 unfinished and 180 empty operations, rather than accepting one failed aggregate compilation as evidence for all atoms. The local Apple-clang baseline and a Linux CI g++ run are separate verification environments. TODO starters intentionally contain a failing compile-time assertion until the learner implements the operation.

The examples use explicit standard headers rather than non-portable `bits/stdc++.h`. They have deterministic outputs, join every worker, and avoid deliberately executing undefined behavior. Address translation, cache-line counts, and false-sharing detection are explicitly parameterized models; they do not claim to benchmark a CPU or expose real physical addresses. Performance-statistic exercises use supplied samples. The fixed illustrative 64-byte alignment is not presented as a universal hardware property.

Finite assertion cases establish the described reference behavior; they do not certify every arbitrary learner implementation or a production trading system. The compilation/linkage lessons demonstrate valid declarations and definitions in a compilable translation unit; the MVP editor is a single-file exercise environment, not a multi-file build workspace. This is a comprehensive staged foundation and systems path rather than exhaustive coverage of every C++ language/library facility. Later work can add project labs, sanitizers, broader generated input banks, custom allocators, coroutine projects, hardware measurements, and advanced C++23 facilities without replacing the existing graph identities.
