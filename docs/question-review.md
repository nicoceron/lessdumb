# Question review

Correctness review of the generated knowledge-point questions (CEN-110), one section per course.

## Competitive Programming

Reviewed October 3, 2026: every non-executed question in `src/lib/knowledge-points/competitive-0.kp.ts` through `competitive-3.kp.ts`. That is 804 conceptual `choose` questions in 192 skills (38, 254, 268, and 244 per file). The 939 predict-the-output questions were not reviewed again, because the catalog tests already execute them.

Each question was read against its point's explanation and worked example. The checks covered the marked answer, every distractor, the question's explanation, and whether the point teaches enough to answer it. Distractors got extra scrutiny for complexity claims: amortized vs worst case, expected vs worst case for hashing, log factors, and Python-specific costs. Disputed behavior was settled by running CPython 3.13. Every flagged item was checked again before editing. A random sample of 22 questions that were not flagged was also re-checked, and it had no errors.

**Result:** no marked answer was wrong, and no correct-choice index changed. Nine questions and one point explanation had confirmed errors, fixed with line-local edits. Three of those questions (0.4%) had a second defensible answer; the other six had a false statement in their explanation or prompt. In all, 9 of 804 questions (1.1%) needed a fix.

### Debatable, left alone

- **Loose upper bounds as distractors.** These are `cp-backtracking-kp3-q4` (`O(n^k · k!)`), `cp-heaps-kp3-q2` (`O(n log n + k)`), and `cp-segment-tree-kp3-q4` (`O(n log n)` to build). Each is a true but loose upper bound. They stand in for misconceptions: counting ordered selections, or sorting first. Every point derives the tight bound the question asks for, and the course never teaches the word "tight". If this needs fixing, one convention sentence in the course would cover all three, rather than three separate edits.
- **Expected vs worst case.** `cp-grids-kp3-q1` (`O(RC)` with set lookups) and `cp-sort-copy-kp2-q4` (`sorted` is O(n log n), though Timsort is O(n) on sorted input) both state the bound the lesson teaches, and no distractor is correct. `cp-hashing-kp1-q4` relies on hash collisions, which are not taught, but it can be answered by elimination.
- **`cp-compression-kp3-q1`.** Sorting dominates only when u log u exceeds n. The prompt implies the worst case, u = n.
- **`cp-recursion-kp3-q3`.** "It grows to about e calls" describes the growth rate. The exact count is about 4e. The distractors are O(log e), halving, and log² e.
- **`cp-tries-kp3-q2`.** The choices put constants inside O(). That informal style is used throughout the course, and the intent (cost depends on prefix length, not word count) is clear.
- **`cp-graph-models-kp2-q4`.** It asks about adjacency matrices, but sits in the point on direction and multiplicity. The skill introduction answers it ("A matrix … offers direct edge lookup"), and kp3 repeats the space cost. Moving it would renumber question IDs.
- **`cp-pointer-count-block-kp1-q4`.** The distractor "always have smaller sums" is false when values repeat; the point says "no larger". It is a deliberate strict-inequality distractor.
- **`cp-interval-overlap-kp1-q4`.** With closed intervals (taught in kp2), a second pair would also be misreported. kp1 states half-open intervals.
- **`cp-combinatorics-kp1-q3`.** "modulo the modulus" refers to a modulus defined in the skill introduction, not in kp1.
- **`cp-lis-tail-position-kp1-q3`.** The marked answer gives the purpose of `bisect_left` rather than its mechanism. No distractor is correct.
- **Wording only.** `cp-scc-finish-order-kp2-q1` (list positions read as vertex labels), `cp-combination-pascal-step-kp1-q2` (the fixed item is introduced in the point, not the prompt), `cp-grids-kp1-q2`, `cp-compression-kp1-q4`, `cp-fenwick-kp3-q3`, and `cp-segment-query-boundaries-kp2-q3`.
